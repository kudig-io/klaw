## 简介
本指南面向首次接触 Klaw 平台的用户，提供从零开始的完整部署流程。你将了解环境要求、依赖安装、三种部署方式（本地二进制、Docker容器化、kind+Helm）、配置文件设置、服务启动与基本使用示例，并附带常见问题与排错建议。目标是帮助你在最短时间内运行并体验平台功能。

## 环境要求
### 系统要求
- **Go**: 建议使用 1.24+ 版本（参见 go.mod）
- **Node.js**: 建议使用 20+ 版本（参见 web/package.json）

- **Kubernetes**: 本地可用 Kind 或任意兼容 v1.24+ 的集群

- CPU: 2核+
- 内存: 4GB+
- 磁盘: 10GB+ 可用空间

## 三种部署方式

### 方式一：本地二进制部署
适合开发和测试环境，快速验证功能。

#### 步骤1：构建应用
```bash
# 构建前端和后端
make build

# 或直接运行（自动构建）
make run
```

#### 步骤2：配置环境变量
```bash
# 设置 Kubernetes 连接
export KUBECONFIG=~/.kube/config

# 设置 API Token（可选）
export KLAW_API_TOKEN=your-secret-token
```

#### 步骤3：启动服务
```bash
# 直接运行二进制文件
./klaw

# 或使用 Makefile 目标
make run
```

服务将在 http://localhost:8080 启动。

### 方式二：Docker容器化部署
适合生产环境和标准化部署。

#### 步骤1：构建镜像
```bash
# 使用 Makefile 构建
make docker-build

# 或直接使用 Dockerfile
docker build -t klaw:latest .
```

#### 步骤2：运行容器
```bash
# 基础运行
docker run -d \
  -p 8080:8080 \
  --name klaw \
  klaw:latest

# 带配置挂载的运行
docker run -d \
  -p 8080:8080 \
  -v ~/.kube/config:/root/.kube/config \
  -v $(PWD)/configs/config.yaml:/app/configs/config.yaml \
  --name klaw \
  klaw:latest
```

#### 步骤3：管理容器
```bash
# 停止容器
make docker-stop

# 清理容器和镜像
make docker-clean
```

### 方式三：Kind + Helm 部署
适合完整的 Kubernetes 环境测试和生产部署。

#### 步骤1：创建 Kind 集群
```bash
# 检查依赖
./deployment/kind/manage.sh check

# 创建集群
./deployment/kind/manage.sh create

# 查看集群状态
./deployment/kind/manage.sh status
```

#### 步骤2：构建并加载镜像
```bash
# 构建镜像
docker build -t kudig-io/klaw:dev .

# 加载到 Kind 集群
kind load docker-image kudig-io/klaw:dev --name klaw-test
```

#### 步骤3：使用 Helm 部署
```bash
# 安装 Helm Chart
helm install klaw ./helm/klaw \
  -f helm/klaw/values-kind.yaml \
  -n klaw --create-namespace --wait

# 端口转发访问
kubectl port-forward -n klaw svc/klaw 18080:8080
```

#### 步骤4：管理集群
```bash
# 卸载
make helm-uninstall

# 升级
make helm-upgrade

# 打包
make helm-package
```

## 命令行接口参考

### 主命令
```bash
# 查看版本信息
klaw version

# 显示帮助
klaw help
```

### 子命令

#### server 命令
启动 Web API + ChatOps 服务。

```bash
# 默认启动（监听 8080 端口）
klaw server

# 指定端口
klaw server --port 9090

# 启用认证
klaw server --auth-enabled=true --api-token=your-token
```

#### diag 命令
对集群运行诊断分析（支持 70+ 分析器）。

```bash
# 运行完整诊断
klaw diag

# 指定集群
klaw diag --cluster=my-cluster

# 输出格式选择
klaw diag --format=json --output=./diagnosis-report.json
```

#### version 命令
打印版本信息。

```bash
klaw version
# 输出: klaw v1.0.0-fusion (诊断核心已集成)
```

## 配置文件设置

### 配置文件位置
- 默认路径：`configs/config.yaml`
- 示例配置：`configs/config.yaml.example`
- 通过 `--config` 参数指定自定义路径

### 关键配置项

#### Kubernetes 配置
```yaml
kubernetes:
  clusters:
    - name: default
      kubeconfig: ~/.kube/config
      context: minikube
```

#### 消息通道配置
```yaml
messaging:
  dingtalk:
    enabled: false
    app_key: your_app_key
    app_secret: your_app_secret
    webhook: your_webhook_url
    secret: your_secret
  feishu:
    enabled: false
    app_id: your_app_id
    app_secret: your_app_secret
```

#### 服务器配置
```yaml
server:
  port: 8080
  auth:
    enabled: true
    token: change-me  # 或通过环境变量 KLAW_API_TOKEN 注入
  cors:
    allowed_origins: []
```

#### OpenClaw 配置
```yaml
openclaw:
  enabled: true
  skills: ./skills
```

### 环境变量覆盖
敏感配置可通过环境变量覆盖，避免落盘：

```bash
# API Token
export KLAW_API_TOKEN=your-secret-token

# 钉钉配置
export KLAW_DINGTALK_APP_KEY=your-key
export KLAW_DINGTALK_APP_SECRET=your-secret
export KLAW_DINGTALK_WEBHOOK=your-webhook-url
export KLAW_DINGTALK_SECRET=your-secret

# 飞书配置
export KLAW_FEISHU_APP_ID=your-app-id
export KLAW_FEISHU_APP_SECRET=your-app-secret
```

## 故障排查指南

### 常见问题及解决方案

#### 1. 无法连接 Kubernetes
**问题现象**: 后端启动后无法获取集群信息

**解决方案**:
```bash
# 检查 kubeconfig 是否正确
kubectl config current-context

# 检查权限
kubectl get nodes

# 验证网络连通性
kubectl cluster-info
```

#### 2. 端口冲突
**问题现象**: 服务启动失败，提示端口被占用

**解决方案**:
```bash
# 查找占用端口的进程
lsof -i :8080

# 修改配置中的端口
# 编辑 configs/config.yaml
server:
  port: 9090
```

#### 3. 认证失败
**问题现象**: 访问 API 时返回 401 未授权

**解决方案**:
```bash
# 设置正确的 API Token
export KLAW_API_TOKEN=your-correct-token

# 或在配置文件中设置
# server.auth.token: your-token
```

#### 4. 前端无法访问后端
**问题现象**: 前端页面加载正常但 API 请求失败

**解决方案**:
```bash
# 检查 CORS 配置
# 在 configs/config.yaml 中添加允许的源
server:
  cors:
    allowed_origins:
      - http://localhost:3000
      - https://your-domain.com
```

#### 5. Docker 部署问题
**问题现象**: 容器启动后立即退出

**解决方案**:
```bash
# 查看容器日志
docker logs klaw

# 检查配置文件挂载
docker inspect klaw | grep -A 5 Mounts

# 验证配置文件格式
cat configs/config.yaml | python3 -m yaml
```

#### 6. Kind 集群问题
**问题现象**: 无法创建或连接 Kind 集群

**解决方案**:
```bash
# 检查依赖
./deployment/kind/manage.sh check

# 删除并重建集群
./deployment/kind/manage.sh delete
./deployment/kind/manage.sh create

# 导出 kubeconfig
./deployment/kind/manage.sh export-config
```

## 结论
通过以上步骤，你可以在本地快速搭建 Klaw 的开发与演示环境，并在 Kubernetes 上运行生产级服务。推荐的使用方式：

- **开发环境**: 使用本地二进制部署，便于调试和快速迭代
- **测试环境**: 使用 Docker 容器化部署，保证环境一致性
- **生产环境**: 使用 Kind + Helm 部署，实现自动化运维

遇到问题时优先检查配置与日志，逐步缩小范围定位问题。建议结合 Helm/Operator 实现更稳定的部署与生命周期管理。
