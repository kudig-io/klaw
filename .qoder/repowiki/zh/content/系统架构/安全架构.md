## 简介
本技术文档围绕 Klaw 平台的安全架构展开，系统性阐述多层安全防护体系：身份认证、授权控制与审计日志；RBAC 权限模型（角色定义、权限继承、资源访问控制）；安全审计机制（操作日志记录、安全事件检测、合规性检查）；CIS 安全基准检查的自动化评估与修复建议；数据传输加密、存储安全与网络安全防护；以及安全配置指南、漏洞扫描集成与安全事件响应流程。文档面向不同技术背景的读者，提供从概览到代码级细节的分层说明，并辅以可视化图示帮助理解。

**更新** 本次更新重点增强了身份认证和跨域安全控制，新增了Bearer Token认证中间件和基于白名单的CORS支持。

## 架构总览

- 接入层：API Server 作为统一入口，执行请求解析、鉴权前置校验与审计埋点。

- 基础设施层：配置中心、消息通道、外部系统（CI/CD、工单、SIEM）。

## 详细组件分析

### Bearer Token认证中间件
**新增** 实现了基于Bearer Token的API认证机制，保护所有 /api/* 路由（健康检查与指标端点除外）。

- **工作原理**：
  - 检查请求是否以 `/api` 开头
  - 验证 `Authorization` 头部是否包含 `Bearer ` 前缀
  - 使用常量时间比较验证Token有效性，防止时序攻击
  - 未通过认证的请求返回401状态码

- **安全特性**：
  - 使用 `crypto/subtle.ConstantTimeCompare` 进行安全的Token比较
  - 支持环境变量注入敏感Token，避免配置文件泄露
  - 可选启用/禁用认证功能

- **配置方式**：
  ```yaml
  server:
    auth:
      enabled: true
      token: your-secret-token
  ```

### CORS跨域控制中间件
**新增** 实现了基于白名单的跨域请求控制，支持预检请求处理和灵活的域名白名单配置。

- **工作原理**：
  - 维护允许的源列表（AllowedOrigins）
  - 检查请求的Origin头部是否在白名单中
  - 设置适当的CORS响应头（Access-Control-Allow-Origin, Methods, Headers）
  - 处理OPTIONS预检请求，返回204状态码

- **安全特性**：
  - 默认仅允许同源请求（未配置白名单时）
  - 支持通配符 `*` 允许所有来源（生产环境不建议）
  - 正确设置Vary头部，确保缓存正确性
  - 限制允许的HTTP方法和头部字段

- **配置方式**：
  ```yaml
  server:
    cors:
      allowed_origins:
        - https://klaw.example.com
        - https://admin.example.com
  ```

## 故障排查指南
- 常见问题：
  - 审计日志丢失：检查写入队列、磁盘空间与权限。
  - 安全事件未告警：确认事件分类与阈值配置。
  - CIS/RBAC 检查失败：核对规则集版本与目标环境差异。
  - 自动修复失败：查看执行日志与回滚状态。
  - 通知未送达：检查通道配置与网络连通性。
  - **新增** 认证失败：检查Authorization头部格式和Token配置。
  - **新增** CORS错误：确认Origin白名单配置和浏览器预检请求。
- 定位步骤：
  - 通过结构化日志检索追踪 ID。
  - 使用 SARIF 报告定位问题根因。
  - 结合诊断结果与修复建议逐步验证。
  - **新增** 检查中间件链顺序和执行结果。
