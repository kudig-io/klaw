模块采用「高层助手 → 抽象接口 → 具体实现 → SDK」的单向依赖分层：
- `assistant.go` 暴露 `Assistant` 结构体，对外提供 `AnalyzeWithAI`、`ExplainIssue`、`GetFixCommands`、`IsAvailable` 等便捷方法，内部委托给 `Provider` 并统一处理超时与空结果回退。
- `provider.go` 定义 `Provider` 接口（`Analyze`/`GenerateSummary`/`SuggestFixes`/`Name`）及共享数据结构 `AnalysisResult`、`FixSuggestion`、`Config`；当前唯一实现为 `OpenAIProvider`，基于 `github.com/sashabaranov/go-openai` 发起 Chat Completion 请求。
- `Factory.CreateProvider()` 根据 `config.Provider`（openai/qwen/mimo/ollama）补齐默认 BaseURL/Model 与鉴权要求，其中 mimo 按 APIKey 前缀（sk-/tp-）自动路由到不同端点，ollama 允许空 Key 并默认本地地址。
- 配置通过 `LoadConfig()` 从 `KUDIG_AI_*` 系列环境变量加载，使用 `env:`/`default:` struct tag 配合 `getEnv`/`getEnvInt`/`getEnvFloat` 统一解析。
- 响应解析遵循 JSON 优先、中文键映射、纯文本降级三层策略，确保对 LLM 输出格式变化具备鲁棒性。
- 测试文件 `provider_test.go` 覆盖配置加载、工厂创建、默认值与非法环境值回退行为，无需外部服务即可运行。
