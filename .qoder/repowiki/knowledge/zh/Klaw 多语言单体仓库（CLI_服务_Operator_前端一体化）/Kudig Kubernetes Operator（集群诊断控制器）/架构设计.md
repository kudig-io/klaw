模块采用标准的 Kubernetes Operator 分层结构：
- `api/v1/` 定义三个自定义资源类型（ClusterDiagnostic、NodeDiagnostic、DiagnosticSchedule），每个类型包含 Spec/Status 结构体并通过 kubebuilder 注解声明 CRD 元数据与 RBAC，`zz_generated.deepcopy.go` 由 controller-gen 自动生成。
- `controllers/` 实现对应的 Reconciler（ClusterDiagnosticReconciler、NodeDiagnosticReconciler、DiagnosticScheduleReconciler），每个 Reconciler 持有 `client.Client` 和 `*runtime.Scheme`，通过 `SetupWithManager` 注册到 Manager，使用 `Owns` 监听下游 Job/ConfigMap 等子资源。
- `cmd/main.go` 作为唯一入口，初始化 scheme、配置 metrics/webhook/健康探针、启用 leader election（ID 为 `klaw-operator.kudig.io`），并依次 SetupWithManager 三个控制器。
- 控制器通过创建 `batchv1.Job`（命名空间固定为 `klaw-system`，镜像 `kudig-io/klaw:latest`）执行实际诊断，结果通过 ConfigMap（`klaw-result-{name}`）回传，Reconciler 轮询 Job 状态并更新 CRD Status。
- `helm/kudig-operator/` 提供 Helm Chart（Chart.yaml + templates/deployment.yaml/rbac.yaml/crds.yaml），`config/` 存放 CRD YAML 与示例资源。
- 依赖方向单向：main → controllers → api/v1，控制器不反向依赖 API 包以外的代码。
