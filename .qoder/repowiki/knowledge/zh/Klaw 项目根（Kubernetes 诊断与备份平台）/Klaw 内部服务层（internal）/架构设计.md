internal/ 下各子模块按职责垂直切分，通过以下横向机制协作：
- 统一持久化：storage.Store 是所有需要落地的模块（audit、backup、automation、tenancy、monitoring 等）共享的 SQLite 键值文档存储，提供 JSON 序列化与并发安全写入。
- 统一配置：config.Config 由 api/server.go 启动时加载并注入到各 Manager/Service 中，保证集群连接、通知渠道、分析规则等配置一致性。
- 事件驱动：events 模块监听 Kubernetes 事件后通过 messaging 抽象层（钉钉/飞书插件）推送告警，同时被 monitoring_metrics 和 alerting 复用。
- 诊断流水线：diag_pipeline 作为在线诊断入口，编排 collector/analyzer/rca/autofix/reporter 等子模块，输出结构化结果供 API 层暴露。
- API 路由：api/server.go 集中注册所有 HTTP 处理器，将外部请求分发到对应业务 Manager（如 backup.Manager、automation.Manager、audit.Logger 等），形成「API → Manager → 领域逻辑 → storage」的分层。
- 分析器族：loganalysis/networkanalysis/rbacanalysis/storageanalysis 遵循统一的 Analyzer 接口模式，便于扩展新的分析维度。
